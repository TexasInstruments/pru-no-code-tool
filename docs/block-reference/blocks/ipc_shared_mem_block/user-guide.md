# IPC Shared Memory (`ipc_shared_mem_block`) — User Guide

> Generated by `build_block_docs.js`.

## What it does

Defines an IPC Shared Memory structure.

Creates a shared memory bridge for passing data between PRU and R5F Host.

## Parameters

| Parameter | Display name | Default | Options |
|---|---|---|---|
| `variableName` | Variable Name | `encoder_data` | — |
| `memorySection` | Memory Section | `PRU_SHARED_RAM` | `PRU_SHARED_RAM`, `PRU_DRAM_0` |
| `dataType` | Data Type | `uint32_t` | `uint32_t`, `int32_t`, `float` |
| `crossCoreWriters` | Also written by another core | `false` | — |
| `noOfCycles` | Number Of Cycles | `4` | — |

## Ports

| Port | Type |
|---|---|
| `prev` | `IO_PREV` |
| `next` | `IO_NEXT` |
| `input1` | `input32` |

## How to use

1. In SysConfig (PRU No-Code), add a **IPC Shared Memory** block to your PRU core's flow.
2. Set the parameters above; wire `prev`/`next` to sequence it, and any `input`/`output` data ports to neighbouring blocks.
3. Generate — the block emits its `m_ipc_shmem_write` invocation into the PRU assembly.

## Notes

- Invalid configurations are rejected by SysConfig with the validation messages listed in the [design doc](./design.md).
- Timing constants are in PRU clock cycles; confirm any `TODO`/`VERIFY` lines against your SoC TRM before flashing.
