# PRU<->PRU scratchpad (XFR) (`pru_spad_block`) — User Guide

> Generated by `build_block_docs.js`.

## What it does

A8 PRU<->PRU scratchpad (broadside XFR) block.

The PRU-ICSS scratchpad is 3 banks of 30 x 32-bit registers, shared by both PRU cores.

## Parameters

| Parameter | Display name | Default | Options |
|---|---|---|---|
| `role` | Role | `producer` | `producer`, `consumer` |
| `bank` | Scratchpad Bank | `0` | `0`, `1`, `2` |
| `baseReg` | First Transfer Register (R#) | `5` | — |
| `wordCount` | Data Words (32-bit) | `4` | — |
| `handshake` | Handshake | `seq` | `none`, `seq` |
| `signalEvent` | Signal Peer PRU After Xout | `false` | — |
| `pruEvent` | PRU System Event Number | `18` | — |
| `demoValue` | Producer Demo Payload Word | `0` | — |
| `noOfCycles` | Number Of Cycles | `1` | — |

## Ports

| Port | Type |
|---|---|
| `prev` | `IO_PREV` |
| `next` | `IO_NEXT` |

## How to use

1. In SysConfig (PRU No-Code), add a **PRU<->PRU scratchpad (XFR)** block to your PRU core's flow.
2. Set the parameters above; wire `prev`/`next` to sequence it, and any `input`/`output` data ports to neighbouring blocks.
3. Generate — the block emits its `m_pru_spad_run` invocation into the PRU assembly.

## Notes

- Invalid configurations are rejected by SysConfig with the validation messages listed in the [design doc](./design.md).
- Timing constants are in PRU clock cycles; confirm any `TODO`/`VERIFY` lines against your SoC TRM before flashing.
