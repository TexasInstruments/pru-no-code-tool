# Tamagawa Initiator (`tamagawa_initiator_block`) — User Guide

> Generated by `build_block_docs.js` on 2026-10-21.

## What it does

Tamagawa protocol initiator leveraging Motor Control SDK.

Interfaces with the Tamagawa encoder via PRU. Simulator only implements payload parsing tests due to UART NRZ timing constraints at 2.5 Mbps.

## Parameters

| Parameter | Display name | Default | Options |
|---|---|---|---|
| `baudRate` | Baud Rate | `2500000` | — |
| `txPin` | TX Pin | `0` | — |
| `rxPin` | RX Pin | `1` | — |
| `dataId` | Data ID | `3` | — |
| `noOfCycles` | Number Of Cycles | `500` | — |

## Ports

| Port | Type |
|---|---|
| `prev` | `IO_PREV` |
| `next` | `IO_NEXT` |
| `output1` | `output32` |

## How to use

1. In SysConfig (PRU No-Code), add a **Tamagawa Initiator** block to your PRU core's flow.
2. Set the parameters above; wire `prev`/`next` to sequence it, and any `input`/`output` data ports to neighbouring blocks.
3. Generate — the block emits its `m_tamagawa_read` invocation into the PRU assembly.

## Notes

- Invalid configurations are rejected by SysConfig with the validation messages listed in the [design doc](./design.md).
- Timing constants are in PRU clock cycles; confirm any `TODO`/`VERIFY` lines against your SoC TRM before flashing.
