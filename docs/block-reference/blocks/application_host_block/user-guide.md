# Application Host (R5F) (`application_host_block`) — User Guide

> Generated by `build_block_docs.js` on 2026-10-21.

## What it does

Generates R5F host code to load PRU firmware and handle IPC.

Creates a main.c for the R5F core that initializes the Sciclient, loads PRU firmware, and reads shared memory for encoder positions.

## Parameters

| Parameter | Display name | Default | Options |
|---|---|---|---|
| `enableSciclient` | Initialize Sciclient | `true` | — |
| `enableIpcNotify` | Initialize IPC Notify | `true` | — |
| `pru0FirmwareName` | PRU0 Firmware Array | `TXPRU0Firmware_0` | — |
| `pru1FirmwareName` | PRU1 Firmware Array | `TXPRU1Firmware_0` | — |
| `noOfCycles` | Number Of Cycles | `0` | — |

## Ports

| Port | Type |
|---|---|
| `prev` | `IO_PREV` |
| `next` | `IO_NEXT` |

## How to use

1. In SysConfig (PRU No-Code), add a **Application Host (R5F)** block to your PRU core's flow.
2. Set the parameters above; wire `prev`/`next` to sequence it, and any `input`/`output` data ports to neighbouring blocks.
3. Generate — the block emits its `m_host_app_none` invocation into the PRU assembly.

## Notes

- Invalid configurations are rejected by SysConfig with the validation messages listed in the [design doc](./design.md).
- Timing constants are in PRU clock cycles; confirm any `TODO`/`VERIFY` lines against your SoC TRM before flashing.
